What the Coordinator is

The Coordinator is an AI that belongs to one project. In the app it is described exactly like this: an AI that takes a goal, splits the work into separate conversations, follows the agents and tells you when it needs you.

Without it, you talk to one agent at a time. With it, you describe the result you want once and the Coordinator does the managing: it writes the plan, decides which part goes to which agent, starts them, reads their answers, sends work back when a check fails and gives you a short report at the end.

Every agent it starts is a normal Codevalanche conversation. You can open it, read everything it did, approve its requests and write to it directly. Nothing happens in a hidden place.

Create a project with a Coordinator

  1. Open “New project” from the left bar.
  2. Name it. Any name from 1 to 120 characters.
  3. Write the goal (optional). In What do you want to work on? describe the result, for example “an online shop with a cart and card payments”. If you write one, the Coordinator starts on it as soon as the project opens. Leave it empty to start from the project's page.
  4. Choose where it works. Under Context, pick Add a folder for code already on your PC, or Clone a GitHub repository. With no folder, the project gets a new folder of its own.
  5. Press Create project. The project opens with its Coordinator on top.

The Coordinator needs at least one connected AI. If none is connected you will see No AI is connected: connect one in Your AIs and the Coordinator and its agents start by themselves.

The Coordinator is marked experimental in the app. It works while this computer is on and Codevalanche is running.

A project you created without the Coordinator can turn it on later from Project settings › Coordinator.

How a goal becomes finished work

1. The plan

The Coordinator reads your goal, the project's folders, its memory and your instructions, then writes The plan: a list of tasks with a counter such as “2 of 4 done”.

2. The agents

Each task becomes its own conversation with an agent, marked Task from the Coordinator. Agents use the model you chose in Model for agents, or the Coordinator's model if you left it on Same as the coordinator. When all places are busy, a task waits with In the queue: it starts when a place frees up.

3. The checks

When an agent says it is done, the Coordinator checks the work, running the project's tests when it can. A task that passes is marked Verified, often with the number of tests that passed. If the check fails, the Coordinator sends it back to the agent with a note and counts the round.

4. The report

When everything is finished you get a clear account, not a vague “done”: “The goal is done. Here is what was checked and what was not”, with a line such as “5 verified · 1 not verified”. Work the Coordinator could not verify is always labelled that way, with the reason.

When it needs you

The Coordinator handles the routine work, but some decisions stay yours. Questions about missing information always need your answer, and each agent’s AI app still checks its own tool permissions. Agents still follow the approval rules of their conversation, so a command or file change that needs permission shows up with Allow and Deny. Questions show up with Reply.

  • The project's list shows how many tasks need you, for example “2 need you”. Use Show only what needs you to hide everything else.
  • When you come back after a while, While you were away sums up what was verified, finished, failed, stopped or restarted, and what is still waiting for you.
  • When a check keeps failing, the Coordinator asks: “The check still fails after 3 rounds. Try another model, or stop this task?” You can pick a different model with one click.

If an agent goes silent for a long time, the Coordinator nudges it, then restarts it once. Only if it is still silent after that does it stop and wait for you.

Talking to the Coordinator and to agents

Write to the Coordinator in its own box (Write to the Coordinator…) to change direction, add a task or ask how things stand. When you say how you want it to work, it can save that as one of Your rules.

You can also open any agent's conversation and write to it directly. The Coordinator sees that too: the agent's conversation shows “The coordinator sees this message too”, and the Coordinator notes “You wrote to … directly · I'll take it into account”. A message you send to an agent through the Coordinator is marked “Delivered … · the Coordinator sees it before its next decision”.

Your own actions are respected. If you close, reopen, rename or delete an agent's conversation, the Coordinator records it and plans around it.

Branches and merging

When agents work on their own git branches, the Coordinator merges each finished branch back and says so, for example “branch … was merged into main”. It never forces a merge:

  • If the project folder has unsaved changes in git, or is on no branch, the merge waits and happens by itself once that is fixed.
  • If two branches conflict, nothing is merged. You see the conflicting files and choose I'll do it or Let the coordinator. In the second case an agent resolves the conflict, the result is checked again and then merged.

Pause, turn off, turn back on

While the Coordinator is paused, nothing new starts and your messages wait in a queue until you resume.

Turning the Coordinator off (project menu › Turn off the Coordinator) stops its agents. Nothing is deleted. Turn it back on, or simply send it a message, and it continues where it left off.

Archiving or removing a project also stops its Coordinator's agents. Removing a project takes it out of Codevalanche, but the files in its folder stay on your computer.

Settings that shape the Coordinator

Open Project settings › Coordinator:

Coordinator modelThe model that splits the work and starts the conversations.
Model for agentsUsed by the agents it starts from now on. Conversations you open yourself use what you choose in the composer.
Continue on its own after the limit resetsOn: an agent that hits its plan's limit waits and continues by itself. Off: it stops and tells you.
Instructions for the coordinatorWhat you want it to achieve and how to work. It reads them with every message.

Write goals that work well

  • Describe the result, not the steps. “Visitors can book a 30-minute slot and get a reminder email the day before” is better than “make a calendar”.
  • Say how to check it. “All tests pass and the booking page works on a phone” gives the Coordinator something to verify.
  • Name the limits. Things not to touch, libraries to avoid, a branch to use. Put lasting rules in the instructions so you write them once.
  • Start with the starters. A new project offers Check the project, Make a plan, Pick up recent work and Use my tools if you are not sure where to begin.

Questions

Do I have to use the Coordinator?

No. A project works without it, as a place that keeps your conversations about one piece of work together. Turn it on when you want the work split between agents.

Which AI does the Coordinator use?

Any AI you connected in Your AIs. You choose the Coordinator's model and, separately, the model for its agents.

Can the Coordinator do things I did not allow?

No. Its agents ask for permission under the same rules as any conversation, and those requests come to you.

What happens if the AI's usage limit runs out mid-goal?

Affected tasks show “Waiting for limit”. With “Continue on its own after the limit resets” on, they continue when the limit resets; otherwise they stop and tell you.

Does turning it off lose my work?

No. Its agents stop, nothing is deleted, and it continues where it left off when you turn it back on.
