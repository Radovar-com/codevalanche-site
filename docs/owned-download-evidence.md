# Owned download evidence

Release activation is separate from this implementation. `supabase/functions/_shared/download-manifest.json` currently has no qualified assets, origins or gateway URL. The site renders release-in-preparation controls, and the public gateway returns `not_configured`. No binary, provider counter, native ledger or transfer delivery source has been qualified by these changes.

The reviewed manifest contains version 1, an HTTPS `gatewayBaseUrl` ending in `/functions/v1/download-redirect/v1`, exact HTTPS `allowedOrigins`, and `assets` with siteId, platform (`windows`, `mac-arm`, `mac-intel`, `linux`), architecture, releaseId, artifactId, qualified=true and targetUrl. Targets must have no credentials, query or fragment; IDs must be bounded safe catalog identifiers. Each site/platform has at most one current public link. Ambiguous route definitions fail closed. The build derives public config from this same manifest. `downloads.js` initializes ordinary native links independently of the optional SDK; analytics never prevents default navigation or awaits a click ACK.

`GET /functions/v1/download-redirect/v1/:siteId/:platform/:releaseId/:artifactId` issues a 302 only for an exact manifest asset. Arbitrary query arguments and malformed routes get 400; an unconfigured asset gets 404. HEAD redirects for availability checks without incrementing the request count; other methods get 405. All responses use no-store and no-referrer. A 302 is gateway intent evidence, not upstream availability or completed transfer evidence. Direct gateway requests and repeated GETs count separately; direct provider links bypass the gateway. Range/retry semantics remain with the provider. No large binary proxy is introduced.

`createDownloadRedirectHandler({manifest?,record?,waitUntil?})` is the actual production factory. Its default is the bundled trusted manifest. Test injection is server-side only; neither request input nor public browser config supplies gateway authority. `record` is best effort and its rejection, exception or stalled promise cannot delay a valid redirect. The deployed entry point calls `createDownloadEvidenceStore(service)` and `EdgeRuntime.waitUntil`; `supabase/config.toml` declares this public function with verify_jwt=false. Optional consent, cookies, W receipt/session/browser IDs, account IDs, query, target URL, IP and UA never enter the evidence payload. Production code does not print requests/errors. Hosting access-log qualification remains a separate release gate.

Migration005 adds `wa_download_requests` (request_id, event_name, site_id, platform, architecture, release_id, artifact_id, observed_at, generated response_class and normalized_error) and `wa_download_daily` (UTC day plus those dimensions, count, watermark). `wa_record_download_request(uuid,text,text,text,text,text,text,timestamptz)` inserts once by gateway-issued request UUID and atomically increments the UTC daily count. An identical UUID replay is a no-op; conflicting reuse is rejected. UUIDs identify requests, never visitors. The only event names are download_redirected and download_request_failed. A failed unknown asset is normalized to unknown release/artifact, without retaining attacker-provided route IDs. Evidence failures can undercount requests; absence of rows is not a zero-traffic guarantee.

The existing 001 `wa_source_snapshots` is reused for trusted provider counters, adding count_delta, asset_removed and source_watermark_high_water. `importReleaseAssetSnapshot(service,snapshot)` calls `wa_import_release_asset_snapshot(text,text,text,bigint,timestamptz,timestamptz,boolean)`. Input snapshot is {siteId,source:'release_provider',releaseId,artifactId,countTotal,observedAt,sourceWatermark,assetRemoved}. The RPC serializes by site/provider/artifact; repeated identical snapshots return duplicate=true, conflicting same-time snapshots and out-of-order observation/watermark arrivals are rejected. First samples, changed releases, and reappearing assets after removal establish a baseline with null delta. Decreasing counters are reset with null delta; deletion is asset_removed with null delta. Only consecutive compatible measured counters produce a nonnegative delta. These deltas compare counters across the observation interval, never exact download timestamps, unique people, completed files or installs. The previous provider/site/artifact/time unique key is preserved, including its rejection of conflicting release identity at the same timestamp.

A null provider watermark is accepted as unknown freshness and never erases the last known ordering boundary. Each row carries the greatest known non-null provider watermark for its site/provider/artifact in source_watermark_high_water, across release changes as well as null observations. New non-null watermarks below that boundary reject; equality is permitted without asserting any new freshness. The actual source_watermark remains null on an unknown observation, even when its carried boundary is known. RPC results expose {counterStatus,countDelta,duplicate,sourceWatermark,sourceWatermarkHighWater,sourceFreshness:'known'|'unknown'}. known means only that the row has a provider timestamp, not that the provider advanced or is current. measured is only a counter-comparison status; with sourceFreshness=unknown, neither observed_at nor the carried boundary may be used as newly verified provider freshness. The pure reconcileReleaseAssetSnapshot helper computes counter rules only; the RPC owns serialized ordering/provenance.

Null-row replay returns its immutable original provenance, including after subsequent recovery; conflicting count or watermark reuse rejects. Retention can delete an old known snapshot while newer unknown snapshots retain its ordering boundary on their own rows. This carried non-identifying validation state is not a substitute provider observation. Once all rows for an artifact have expired, its ordering history also expires and the next snapshot starts a new baseline. No provider state is retained indefinitely outside the bounded snapshot store.

All D tables have RLS enabled, no anon/authenticated policies or privileges, and service_role-only CRUD/RPC grants. `wa_prune_download_evidence(timestamptz default now())` removes request rows older than 90 days and non-identifying daily counters/provider snapshots older than 13 months. A separately approved maintenance schedule must invoke it; this task creates no job or infrastructure. Request UUID replay protection is bounded by raw retention. Raw rows allow exact retained timestamp boundaries; archival daily counts are UTC-only. After 90 days, Bucharest/local-day or partial-UTC-day boundaries are unsupported, and UTC date labels must never be shifted and presented as exact local counts. W-only filters such as acquisition, campaign, page or trafficClass cannot be applied to D counters without a separately approved consent-qualified correlation contract.

`downloadCoverage()` exposes absent provider, delivery and native sources as not_configured; explicitly configured but unavailable adapters return unavailable. No provider or native importer is activated here. transfer_served requires separately qualified distribution delivery evidence; 206/range/request counts are insufficient. First observed native open and activation require the existing qualified P4 account population; Guest remains product-eligible while Guest activation is unmeasured. There is no D/W/person/activation conversion rate from these counters.

The SDK's per-client release registry is derived from the public reviewed manifest, including when creating an account-purpose client on the same host; all other registry and consent rules remain unchanged. Queue validation uses that registry without relabeling events or changing purpose/principal/generation. The collector factory uses its bundled manifest by default; an internal downloadManifest option supports local production-path fixtures. Its request body cannot supply a registry. Configured public releases require the gateway, collector and website to ship the same reviewed manifest. SDK builds pair C/src/analytics and R/public/analytics distributions with matching hashes; no R React source is changed.

Local fixtures exercise the production handler, SQL RPCs, native link and dedicated click validation with synthetic release IDs and fixture payloads. Browser transport rewrites the synthetic HTTPS artifact redirect to a local HTML fixture after asserting the production Location; no real release/provider/artifact request is sent. These fixtures do not qualify an actual release. T12 still owns approved artifact/provider/log verification, migration/function activation, maintenance scheduling, rollback manifest, and publication.
